API 体系总览

PowerCMS 12 是 Headless CMS：内容模型与内容统一存储，任何前端（网站、App、小程序、大屏）都可以通过标准接口取数渲染。开放面包括：

通道入口用途
管理端 REST API/api/v1/...站点、内容模型、内容、媒体、工作流等后台能力；需认证
Delivery API/api/v1/delivery/...面向前台站点的公开只读取数接口
GraphQL/graphql/sites/{siteId}按站点查询内容，一次请求取关联结构
MCP Server/api/mcp面向 AI 客户端的标准 MCP 工具面
OpenAPI 文档/swagger-ui.html 与 /v3/api-docs在线浏览与调试全部 REST 端点，可直接导出 OpenAPI 定义
本文示例中的 {siteId} 均为站点 UUID，可在管理端「站点」页或 GET /api/v1/sites 返回结果中获取。建议开发时对照你所在环境的 Swagger 页面核对参数细节。

认证与授权

2.1 会话登录（管理端 / 脚本）

POST /api/v1/auth/login Content-Type: application/json {"username": "admin", "password": "******"} # 200 OK {"authenticated": true, "username": "admin", "loginMode": "BACKEND"}

登录成功后建立会话 Cookie；GET /api/v1/auth/me / /auth/status 可查询当前登录状态，POST /api/v1/auth/logout 退出。后台登录与前台会员登录是不同通道（/auth/backend/login 与 /auth/frontend/login），后台会话才可访问管理 API。

2.2 API Token（服务端集成推荐）

在管理端「个人中心」创建 API Token（对应 POST /api/v1/me/tokens），之后以 Bearer 方式调用，适合 CI 脚本与服务端集成：

curl -H "Authorization: Bearer pcm_xxxxxxxx" \ https://<host>:8080/api/v1/sites
  • Token 前缀 pcm_...；OAuth 访问令牌为 pcm_oat_...（配合 /oauth/token 等标准端点，绑定 DPoP 时需携带匹配的 DPoP 证明）；
  • 令牌过期与非法返回可区分的 401（含 RFC 6750 invalid_token 挑战），调用方可据此判断是否重新签发；
  • 可随时在 DELETE /api/v1/me/tokens/{id} 吊销。

2.3 统一错误体

所有 JSON 接口的错误返回统一结构，traceId 可直接用于运维排查：

{"code": "BAD_REQUEST", "message": "请求参数错误", "traceId": "3a84fa0d090a40308cdddf2cb9eece1b", "details": []}

查询结果中，内容模型的自定义字段同时以 fields 对象与平铺键两种形式返回（字段名带类型后缀，如 tel_s、sort_order_i）：

curl "https://<host>:8080/api/v1/delivery/sites/{siteId}/contents/query?contentType=about-contact&limit=1" [{ "id": "093e3c5b-...", "title": "宝丽星通联系方式", "status": "PUBLISHED", "routePath": null, "fields": { "tel_s": "010-62129317", "sales_s": "sales@example.com" }, "tel_s": "010-62129317", "sales_s": "sales@example.com" }]
Delivery API 默认匿名可读。若站点内容涉密，可通过访问策略限制公开范围，仅放行需要公开的模型与字段。

4.1 站点应用（webapps）部署与取数

除 Headless 取数与 MVC 渲染外，12.0.1 起可把 React / Vue 前端产物直接部署为「站点应用」：

  • 按站点 Key 部署到 webapps/{siteKey}/，入口 GET /webapps/{siteKey}，匿名公开；
  • 缺失尾斜杠的请求会 302 补斜杠并保留查询参数，避免 Vite 相对资源路径 404；
  • 应用内可相对路径寻址 API（如 ./api/v1/delivery/...），由请求改写过滤器归一到站点维度，前端无需硬编码站点 ID；
  • 资源详情页等场景会自动注入第一方统计脚本 analytics.js，按资源上报 PAGEVIEW / CONTENT_VIEW / DOWNLOAD（预览与编辑态不注入，避免污染统计）。

GraphQL

每个站点拥有独立 GraphQL Schema，适合一次请求取回内容及其关联结构（如文章 + 作者 + 栏目）：

端点说明
POST /graphql/sites/{siteId}标准 GraphQL 查询入口（body 为 {"query": "..."}）
GET /graphql/sites/{siteId}/schema查看该站点的 GraphQL Schema
POST /api/v1/sites/{siteId}/graphql-schema/rebuild内容模型变更后重建站点 Schema（系统管理员）
curl -X POST "https://<host>:8080/graphql/sites/{siteId}" \ -H "Content-Type: application/json" \ -d '{"query":"{ __schema { queryType { name } } }"}'

FreeMarker 模板开发

除了 Headless 取数，PowerCMS 12 也支持服务端渲染：页面、区块与组件模板使用 FreeMarker（.ftl）编写，由平台渲染后输出 HTML。内容类型的 displayTemplate 指向模板路径（如 /templates/about-contact.ftl）。

6.1 渲染模型：顶层变量（以 12.0.1 为准）

模板渲染时平台注入统一的顶层模型。已登记的顶层变量全集如下（引用未登记的顶层名字会在模板保存校验时报错）：

类别变量
页面渲染核心zones（页面区块集合）、renderedZones（已渲染区块 HTML）、renderComponent（渲染组件的方法）、page、currentPage、title、id
内容content、contentModel（当前内容条目，二者同源）、category、fields、pagination
站点与配置site、siteConfig、siteContext、globalProperties、language、locale
请求上下文request、requestParameters、cookies、session、currentUser、now、modePreview（是否预览态）、route、routePath、url
导航navigation、navTreeBuilder、navBreadcrumbBuilder、renderBreadcrumb
主题包装pageBody、body、htmlHead、header、footer
扩展与兼容application、applicationContext、siteItemService、urlTransformationService、crafterEnv、flags 等

6.2 页面模板：区块（Zone）与组件

页面模板由「区块」组织：zones 是「区块 key → 组件实例列表」的 Map，renderedZones 保存各区块的渲染结果。renderComponent 按组件路径（/site/components/...）或引用名渲染组件，还可传入父组件 ID 与附加模型，典型写法：

<#-- 页面骨架模板 --> <!DOCTYPE html> <html lang="${locale}"> <head> <title>${title!""}</title> ${htmlHead!""} </head> <body> ${renderComponent("/site/components/header")} <main> <#-- 按引用名渲染，可选：父组件 ID、附加模型 --> ${renderComponent("/site/components/content-body")} <#-- 直接遍历区块中的组件实例 --> <#list (zones["main"])![] as component> ${renderComponent(component.reference)} </#list> </main> ${renderComponent("/site/components/footer")} </body> </html>

6.3 容器与组件模板

容器模板可使用的顶层变量包括 siteId、pageId 与 contentQuery（在模板中直接按条件查询内容的取数方法）。组件模板可用 content / contentModel（当前组件数据）、params（组件参数）、templateModel 与 additionalModel（附加模型），以及 editableText 方法——输出可被可视化编辑器行内编辑的文本，第一个参数为字段名，后两个为可选的编辑器形态与格式：

<#-- 组件模板示例：图文卡片 --> <div class="card"> <h3>${editableText("title_s")!""}</h3> <p>${editableText("summary_s", "minimal", "text")!""}</p> </div>

6.4 模板校验与最佳实践

  • 落库前试渲染：模板保存时平台会做"顶层严格、数据宽松"的试渲染——引用未登记的顶层名字（如把 @powercms.zone 指向不存在的命名空间）会直接报错，数据字段缺失则放行，便于先存模板后补数据；
  • 对可能缺省的变量统一使用 FreeMarker 空值处理（! 默认值、?? 判空），避免渲染期空指针；
  • 模板放版本库管理（配合 Git 组件），走发布流程进入各环境，避免直接改生产模板；
  • 预览与线上使用同一套渲染引擎（GET /api/v1/preview/page、/preview/template），所见即所得。

可视化组件接入（UVE）

可视化编辑器（UVE）通过 iframe 加载站点预览页，并在编辑态注入桥接脚本 /api/v1/preview/uve-bridge.js。只要模板输出符合下方标记约定，页面即可在编辑器中被选中、拖拽排序与行内编辑。

7.1 结构标记属性

属性位置说明
data-pcms-zone-root区块容器标记一个区块（Zone），值为区块 key
data-pcms-component组件根元素标记组件，值为组件实例 ID，编辑器据此定位与排序
data-pcms-zone组件根元素组件所属区块 key
data-pcms-index组件根元素组件在区块内的序号
data-pcms-kind组件根元素组件类型（如 EMBEDDED）
data-pcms-zone-empty区块容器空区块占位，编辑器显示"添加组件"引导

7.2 行内编辑标记

属性说明
data-pcms-editable-field可编辑字段名，编辑器在此元素上提供行内编辑
data-pcms-editable-component所属组件 ID（缺省取最近祖先组件）
data-pcms-editable-format编辑格式：text（默认）或富文本
data-pcms-editable-mode编辑器形态（默认 minimal）
data-pcms-content-item / data-pcms-content-version关联内容条目与版本，保存时回写对应版本

组件模板中使用 editableText 方法输出的文本会自动携带上述行内编辑标记，无需手写。

7.3 postMessage 协议

桥接脚本通过 postMessage 与编辑器双向通信；在收到带匹配 nonce（页面 URL 的 uveNonce 参数）的 pcms:init 之前保持静默，且只信任编辑器来源：

方向消息说明
预览页 → 编辑器pcms:ready桥接脚本就绪
预览页 → 编辑器pcms:bounds上报区块 / 组件几何信息（选中框、排序基准）
预览页 → 编辑器pcms:component-clicked / pcms:component-hovered组件点击 / 悬停
预览页 → 编辑器pcms:inline-edit-started / -save / -ended行内编辑生命周期与保存内容
编辑器 → 预览页pcms:init { nonce }初始化握手
编辑器 → 预览页pcms:flush-bounds / pcms:reload要求重新上报几何信息 / 重载页面

7.4 预览通道

  • POST /api/v1/preview/token：签发预览令牌（需认证）；
  • GET /api/v1/preview/page / /preview/template / /preview/content / /preview/content-item：按令牌渲染页面、模板或内容预览，未保存草稿也能所见即所得。

MCP Server

面向 AI 客户端，PowerCMS 12 内置标准 MCP Server（端点 /api/mcp），提供 Tools / Resources / Prompts 三类结构化工具面，覆盖内容、站点、工作流、媒体、知识库等域，任何标准 MCP 客户端即插即用；工具面与 REST API 同源，权限模型一致：

content.search # 内容检索 content.draft # 内容起草 flow.todo # 工作流待办
  • 能力分 Tools / Resources / Prompts 三类，双传输并存，协议归一到 MCP 2025-06-18 修订版；
  • 配额与审计：GET /api/v1/mcp/quota 查询配额，/api/v1/sites/{siteId}/mcp-audit 查看调用审计；
  • 工具 Token 权限分 L0 只读 / L1 草稿 / L2 发布三级，只能收窄不能扩大，越级调用返回 403 并落审计。
工具数量与清单随版本演进，建议客户端在初始化时通过标准协议拉取 tools/list，以运行实例的实时清单为准。
